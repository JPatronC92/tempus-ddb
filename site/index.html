The protocol

Intent is not authorization.

An agent can ask for an action, but cannot authorize it. Tempus evaluates a signed intent against deterministic policy, and an executor must consume the bound permit before it can act.

01 / IDENTITY

Sign the request

The requesting workload signs the exact payload it wants executed.

02 / POLICY

Issue a permit

Policy evidence, identity and scope determine an allowed or blocked decision.

03 / EXECUTION

Consume once

The executor verifies the permit's binding, tenant and expiry before any effect.

04 / EVIDENCE

Verify the trace

Intent, authorization and outcome remain cryptographically linked for inspection.

What is in the source

Control the handoff from model to effect.

Tempus is a local-first Rust runtime with Python, CLI and MCP surfaces. It keeps downstream credentials with the executor, rather than in the agent payload.

Control plane

Policy and identity evidence

Signed, versioned rules and workload lifecycle events are bound to each authorization.

  • Ed25519 identities
  • Rotation and revocation
  • Tenant-scoped delegation
Execution plane

Fail-closed permit use

Execution is mediated by a short-lived permit and a single-consumption receipt.

  • Deterministic action IDs
  • Idempotency safeguards
  • UNKNOWN is not retried
Integration plane

Native, CLI and MCP access

Use the same boundary in a local runtime, an audit workflow or constrained GitHub automation.

  • SQLite-backed ledger
  • Vault Transit signer support
  • Issue and pull-request adapter

Release boundary

A public beta, with its limits stated plainly.

v0.4.0 is local-first and single-instance. Distributed permit consumption, independently durable external checkpoints and a live web audit console are not part of the current source line.

Use intentionallyRead the threat model and validate your credential boundary before relying on Tempus for production-critical external effects.
