Local-first B2A security gate

Verify before agents act.

Tempus DDB authorizes narrow agent actions with signed, single-use permits and produces tamper-evident receipts that can be verified end to end.

Authorization lifecycle

A cryptographic boundary between intent and effect.

The runtime validates signed action intents against deterministic policies before an executor can consume a permit. Every completed action produces a signed trace.

Register Agent identities enter a signed registry.
Authorize A signed intent is evaluated against policy.
Execute A permit is consumed exactly once.
Verify Authorization and outcome receipts form a trace.

Included in the source

Built for bounded autonomous actions.

Signed policies & identities

Agent registration, delegation controls, rotation and revocation events are recorded with signed evidence.

Fail-closed permits

Authorizations bind tenant, agent, action, intent hash, expiry and idempotency key before execution.

Verifiable receipts

Authorization and execution receipts can be retrieved and cryptographically verified as a complete action trace.

Local SQLite storage

The native runtime stores the ledger locally using SQLite with WAL mode and pooled executor connections.

GitHub executor

An optional credential-isolated adapter executes a narrow, validated GitHub REST action from a verified permit.

MCP server

Signed request, outcome, trace and registry capabilities are available through a stdio MCP server.

Release boundary

Public beta, with explicit operational limits.

v0.4.0 is a local-first, single-instance beta. It does not yet provide multi-instance coordination or externally durable checkpoints. Evaluate it in a controlled environment before using it for production-critical effects.
